# План автоматизации тестирования сервиса покупки тура "Путешествие дня"

## 1. Перечень автоматизируемых сценариев

Все проверки валидации полей проводятся для обеих форм покупки: **"Оплата по карте"** и **"Кредит по данным карты"**.

### Позитивные сценарии
* Успешная оплата по одобренной карте (`4444 4444 4444 4441`) - отображение уведомления об успехе и запись статуса `APPROVED` в БД.
* Успешная покупка в кредит по одобренной карте (`4444 4444 4444 4441`) - отображение уведомления об успехе и запись статуса `APPROVED` в БД.

### Негативные сценарии
* Отказ в оплате по отклонённой карте (`4444 4444 4444 4442`) - уведомление об отказе и запись статуса `DECLINED` в БД.
* Отказ в кредите по отклонённой карте (`4444 4444 4444 4442`) - уведомление об отказе и запись статуса `DECLINED` в БД.
* Отправка пустой формы - отображение ошибок валидации под полями, отсутствие записи в БД.
* Невалидный номер карты (менее 16 цифр, несуществующая карта, ввод букв и спецсимволов).
* Некорректный месяц (`00`, `13`, ввод одной цифры).
* Некорректный год (прошедший год, например `25`; далёкий будущий год, например `50`; ввод одной цифры).
* Некорректное имя владельца (кириллица, цифры, спецсимволы, граничные значения: `1` символ и `250` символов).
* Некорректный CVC/CVV (менее 3 цифр, ввод букв и спецсимволов).

## 2. Перечень используемых инструментов с обоснованием выбора
* **Python 3** - основной язык разработки автотестов.
* **Pytest** - фреймворк для запуска тестов; выбран за удобную работу с фикстурами и параметризацию однотипных негативных проверок.
* **Selenium WebDriver** - стандартный инструмент для автоматизации взаимодействия с веб-интерфейсом в браузере.
* **PyMySQL** - библиотека для прямого подключения к СУБД MySQL из Python и проверки корректности сохранения статусов операций.
* **Allure** - фреймворк для генерации наглядных отчётов о прохождении тестов со скриншотами при падениях.
* **Docker и Docker Compose** - для быстрого и воспроизводимого разворачивания тестового окружения (MySQL, эмулятор платёжного шлюза и веб-приложение).
* **GitHub** - для хранения кода проекта, истории изменений, отчётных документов и ведения баг-репортов через Issues.

## 3. Возможные риски при автоматизации
* **Нестабильность UI-тестов (flaky-тесты):** из-за задержек ответа от банковского шлюза и анимации всплывающих уведомлений тесты могут падать без настройки явных ожиданий (`WebDriverWait`).
* **Большое количество багов в приложении:** из-за намеренных дефектов в сервисе потребуется дополнительное время на анализ причин падения тестов (ошибка приложения или ошибка в коде теста) и оформление баг-репортов.
* **Нехватка практического опыта:** так как это первый комплексный проект с нуля, интеграция БД и отчётов Allure может занять больше времени, чем при типовых учебных задачах.
